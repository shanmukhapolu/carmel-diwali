Privacy & Security

How volunteer information is protected

The registration system is designed around data minimization, strict Firestore access rules, and controlled administrative access for Carmel Diwali Festival volunteer coordination.

Minimal data collection

The form only collects information needed to register volunteers, coordinate positions and shifts, communicate event details, and administer the festival. It does not collect passwords, financial information, medical information, IP addresses, browser fingerprints, or device IDs.

No public registration reads

Firestore rules deny public browser reads, updates, and deletes for volunteer registration records. Public visitors can submit a validated registration, but cannot browse or download volunteer records.

Validated writes

Security rules allow volunteer registration creation only when the submitted document matches the approved field list, expected data types, size limits, selected position and shift, and required registration fields.

Atomic shift capacity protection

Volunteer capacity is tracked using separate shift counter documents. Transactions reserve an available spot and create the registration together, while security rules prevent the counter from exceeding the configured capacity.

Least-privilege access

Volunteer information is not publicly exposed. Administrative features are restricted to authorized event organizers, and access should be limited to people who need the information to coordinate volunteers, shifts, communications, check-in, or event operations.

Controlled reporting access

Any external reporting or administrative automation should access Firebase through a district-, organization-, or event-controlled service account or approved backend credential. Server-side administrative credentials can bypass browser security rules, so they should never be stored in frontend code.

Important: never place Firebase Admin SDK credentials, service-account private keys, or privileged tokens in this public website. Keep administrative credentials server-side and restrict them to approved event organizers.
